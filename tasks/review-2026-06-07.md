# Codebase review — 2026-06-07

Full read-over of the codebase (overnight, read-only — no code changed). Findings from four
parallel reviewers across providers/poll, storage/security, UI/components, and tests/tooling,
de-duplicated and prioritised. Many map to existing `hardening-backlog.md` items; this is the
"what's actually there" pass to feed the hardening PRD.

**Overall:** solid foundation. One runtime dependency, tokens never logged, MV3 statelessness
correct, shared components genuinely de-duplicate popup/side-panel, and the pure-logic core is
tested thoughtfully. The real gaps are runtime-path resilience (poll concurrency + rate-limit
back-off), test coverage stopping at the pure boundary, and a couple of UX-rule violations.

## Highest value — do first

1. **`poll()` has no single-flight / concurrency guard** (`background/poll.ts`). It's invoked
   from `onAlarm`, `onStartup`, `onInstalled`, and the `poll-now` message — all can overlap
   (manual refresh mid-cycle, or a slow cycle still running at the 0.5-min alarm floor). Each
   cycle does read-modify-write on `snapshots`/`repoEtags`/`rateLimitPausedUntil`; overlapping
   cycles race and a transition can be double-announced or missed. Fix: a module-scoped
   in-flight promise that coalesces concurrent calls.
2. **Rate-limit back-off never engages on an actual 429** (`providers/http.ts` + `poll.ts`).
   The pause (`rateLimitPausedUntil`) only sets on a _successful_ response with `remaining <
FLOOR`; a real 429/403-secondary throws, is caught as a warning, and the next alarm hammers
   the API again. Fix: detect 429/403-rate-limit in `fetchJson`, parse `Retry-After` /
   `x-ratelimit-reset`, surface it so `poll` sets the pause.
3. **Unbounded fetch fan-out** (`poll.ts`). All watched repos fetched in one `Promise.all` — N
   repos = N simultaneous requests, which trips GitHub secondary-rate-limit abuse detection.
   Fix: bound concurrency (pool of ~5–10).
4. **`poll()` and `notify.ts` are untested** — the orchestration heart (seeding, pause,
   `countFailures`, badge, error-keeps-snapshot) and the user-facing signal (badge,
   notification link round-trip). Both are cheaply mockable (`vi.mock` the namespace imports;
   stub `chrome.*`). Highest-value tests to add.
5. **Disabled buttons violate the project rule** (UX: "no disabled buttons except transient
   submit"). `RepoCard.svelte` repo-toggle is `disabled` when a repo has no extra branches;
   `RepoList.svelte` owner toggle is `disabled` in the popup Problems view. Fix: render a
   static non-interactive header in those cases instead of a dead greyed button.

## Correctness / resilience

- **GitHub "newest per ref" trusts default list order** (`providers/github.ts`) — no `sort`
  param; dedupe keeps first-seen, which may not be the most recently _updated_ run for a ref.
  GitLab is explicitly `order_by=updated_at&sort=desc` (correct). Fix: for GitHub, dedupe by
  max `updated_at` per ref (or request a sort).
- **GitLab list endpoint likely ignores `If-None-Match`** — the "304s don't cost budget"
  assumption holds for GitHub, probably not GitLab's pipelines list. Verify; if unsupported,
  document that GitLab always full-fetches and rely on the floor back-off (its 2000/min is
  generous).
- **Per-repo 401 (dead token) is silently swallowed** (`poll.ts` catch). Mitigated because
  `accountHealth` surfaces it via `validateToken`, but consider short-circuiting a repo poll
  when its account health is already known-bad this cycle (avoids N redundant 401s).
- **Fire-and-forget `poll()` in listeners has no `.catch`** (`background/service-worker.ts`
  `onStartup`/`onAlarm`) → unhandled rejection in the worker. Add `.catch(console.warn)`.
- **Timeout/abort surfaces a cryptic message** ("The operation was aborted") into
  `accountHealth.error`. Map `AbortError` → "Request timed out" in `fetchJson`.
- **Early returns skip badge clear + `lastPolledAt`** (`poll.ts`): removing all repos leaves a
  stale red badge and a frozen "updated … ago" footer. Clear badge + stamp time on those exits.

## Security / boundaries (mostly clean)

- **Tokens never logged/synced — verified clean.** Tokens live only in `Authorization` /
  `PRIVATE-TOKEN` headers, never in URLs or error strings; only logs are `repo.name` + dev-only.
  Keep the invariant: never build an error string containing `account.token`.
- **Dev-only modules verified absent from `dist/`** (grep: 0 hits for `dev-chrome`/`seedData`/
  `pipesTheme`/sample names/`import.meta.env`). The top-level `import '../lib/dev-chrome'` relies
  on tree-shaking + the `import.meta.env.DEV` guard; an explicit dynamic `if (DEV) import()` would
  make the exclusion self-evident (see backlog "dev-only boundary").
- **`optional_host_permissions: ['https://*/*']`** is maximally broad but essentially forced
  (self-hosted origins unknown at build time) and gated behind a user gesture. Document the
  justification for the Web Store reviewer.
- **`matchesShape` self-heal is shallow** (`storage.ts`) — it guards container type (array vs
  object) only, not element shape. A malformed-element `accounts`/`snapshots` (e.g. a Record
  whose values aren't arrays) passes and then throws downstream (`byRef`/`.map`). The comment
  over-promises. Fix: either narrow the comment to "guards container type only", or deep-validate
  the few critical shapes. `subscribe` has the same gap vs `get` (no `matchesShape` on `newValue`).

## Config / structure

- **Central config** (already backlogged) — the highest-drift dup is the **`0.5` alarm floor**,
  a literal in both `service-worker.ts` and `options/App.svelte` (UI step) that MUST stay in
  sync. Also: SaaS host strings (`providers/index.ts` + both adapters), badge `FAIL_COLOR`,
  notif id prefixes (`pw-fail-`/`pw-ok-`, an implicit contract with the worker's reclaim), page
  sizes. Consolidate into `src/lib/config.ts`.
- **`storage.set` JSON-clone** is lossless for the current (JSON-safe) shapes; `$state.snapshot()`
  is the framework-blessed deproxy alternative (couples storage.ts to Svelte — optional).

## UI / a11y / CSS

- **Hardcoded `#fff`** in `RepoCard.svelte` `.fail-badge` (and `white` knob in `options`) breaks
  the no-hex-outside-tokens rule. Add a `--status-ink` token (white on status fills) and use it.
- **Dead code:** `Row.svelte` `primary` + `dim` props (no consumer; styles unreachable) — wire
  or remove. `RefChip` is only used by the showcase (Row reimplements the ref treatment inline)
  — delete RefChip or have Row use it. (Confirm intent before removing.)
- **Side-panel `BRANCH_STATES` omits `unknown`** while `ALL_BRANCH_STATES` includes it → "Select
  all" silently drops `unknown` from the persisted filter, and `allStatesOn` can't reflect it.
  Derive the pill list from one source (export the ordered list from `group.ts`).
- **Duplicated storage-wiring** across popup + side panel (the identical `get`+`subscribe` block).
  Extract a `createDashboardState()` rune module (`.svelte.ts`) returning the shared state +
  lifecycle. (The one place the otherwise-good dedup didn't reach.)
- **`options` `loadRepos` mutate-then-spread** + concurrent `loadRepos` (one per account) can
  last-write-win on `availableRepos`. Build the next object once; be aware of the race.
- **Repeated `@keyframes spin`** in 4 files + redundant per-component `prefers-reduced-motion`
  guards — `base.css` already has a global reduced-motion reset, so the per-component guards are
  redundant. Optional cleanup.

## Tests / tooling

- **pre-push vs CI mismatch:** the husky pre-push runs `pnpm test` (incl. the browser project)
  but never `playwright install chromium`; CI does. On a fresh clone the hook fails. Fix: a
  `pretest`/`postinstall` guard, or run only the unit project locally and leave browser to CI.
- **`pnpm build` is not a CI check** — the stale NOTE's precondition (surface entry points) is
  now met; a manifest/crxjs break ships uncaught. Add a `build` job; delete the NOTE.
- **No coverage gate or report** — add a non-gating `--coverage` report now (visibility); defer a
  threshold (backlog says 80%).
- **`countFailingBranches`** (`group.ts`) is exported, untested, and has **no caller** in src —
  test it or remove it (likely dead after the popup rework moved to `PROBLEM_STATES`).
- **Stray `TODO.js` at repo root** — a `.js` scratch note caught by the lint glob. Move into
  `tasks/` or delete.
- **package.json:** `playwright` (direct) vs `@vitest/browser-playwright` (which pulls it) may be
  redundant; `@vitest/browser` direct dep may be a transitive peer. Verify the CI
  `playwright install` need; trim if not required.

## Notable strengths (keep)

- Single runtime dependency; no date/util libs (`RelativeTime` hand-rolled).
- MV3 done right: listeners registered synchronously at top level, no module-global mutable
  state, ephemeral-worker-safe.
- Shared `RepoList`/`TopAlerts`/`UpdatedFooter` remove most surface duplication.
- Pure-logic tests are meaningful (group view-models, status maps, http, storage healing).
- Tokens/focus-visible/reduced-motion/sentence-case discipline is strong.
