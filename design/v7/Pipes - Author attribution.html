Pipes · row attribution

“Who caused this?” — author on every row

A small avatar + truncated name on every Row and ChangeRow, so a red branch or PR/MR shows who at a glance — no click-through. Display only; independent of the All | Mine scope filter. Built on the locked v4 tokens, light + dark, at panel (360px) and popup (440px) widths.

Recommendation: avatar + truncated name on the metadata line, before the time. Default Row stays one line (it’s roomy); the PR/MR ChangeRow goes two lines — title on top, branch · author · time beneath. Split target via stretched row-link + raised author link.

In context — both row types, both widths

Author sits in a fixed slot immediately before the relative time, on the right where the eye already lands for “when”. The status icon (left) and time (right) never move. Hover a row → it opens the run/PR; hover the avatar+name → it opens that person’s profile. Try it.

The nested-anchor problem — and the fix

The whole row is already a single <a> to the run/PR. A profile link is a second destination, and <a>-inside-<a> is invalid. Recommended: a stretched-link split target. The row link is absolutely positioned to fill the row (inset:0); the author is a normal sibling <a> raised above it (z-index:1). One row, two real anchors, valid HTML, two tab stops.

① Row link (run / PR)

.r-link fills the row at z-index:0. Clicking status, title, branch chip or time → the run. Keeps today’s behaviour exactly; no regression.

② Author link (profile)

.author is a sibling <a> at z-index:1, so it “punches through” the overlay and owns its clicks. aria-label="Open Sam Okafor’s profile"; full name also in title.

Focus & keyboard

Two tab stops in DOM order: row link, then author. Row focus ring via .r:has(.r-link:focus-visible); author has its own --brand ring. AA, both schemes.

Fallback (if split-target is fiddly)

Render the author non-linking — avatar + name + title only, no profile link. Simplest; loses click-to-profile but keeps the “who”. Documented as the acceptable fallback.

Avatar states

Avatar is 18px, round (16px in dense rows), greyscale at rest so it never competes with the bright status icons — it comes to full colour on hover / focus. Photo (or bot avatar) when available; otherwise a flat initials swatch. Name truncates with ellipsis at ~64px, full name in the tooltip.

Unknown author

No author data → render nothing (no avatar, no name, no gap). The slot simply collapses; time stays put.

Narrow fallback — avatar only

Name shown by default at panel and popup widths. Below ~336px (or in a forced dense mode) the .author-name hides via a container query, leaving the avatar — which still carries the tooltip and profile link. Status and time never get crowded.

The six decisions

1 · Placement

Fixed slot just before the relative time, right-aligned cluster. Status (left) and time (far right) never move; the title/ref takes the flexible middle and truncates first.

2 · Avatar + name vs avatar-only

Avatar + truncated name by default (panel + popup). Avatar-only below ~336px or in dense mode, via container query. Confirmed.

3 · Truncation

Ellipsis at max-width ~64px (≈ 8–10 chars); full display name in title. Keeps the right cluster bounded so the title gets the slack.

4 · Nested anchor

Split target — stretched row-link + raised author link (two real <a>). Non-linking avatar+name+tooltip is the documented fallback.

5 · Same on both rows

Identical treatment on Row and ChangeRow, so “who” reads consistently whether it’s a main break or a PR/MR.

6 · Avatar

18px round (16px dense). Chain: photo / bot avatar_url → initials on a neutral swatch. Greyscale at rest, colour on hover/focus so the status icons stay the focal point. Flat fallback, full name in title.

Build spec — tokens only

Drop-in markup for both rows. The only structural change is the stretched .r-link + the .author sibling; everything else is your existing row grid.
