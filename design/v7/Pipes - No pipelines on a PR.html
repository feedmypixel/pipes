Pipes · PR / MR row

Open PR with no pipelines

Repos that only run CI on push to main have PRs with zero runs. Today that falls through to the purple ? unknown icon and reads as a problem. The fix: treat “no runs” as the absence of a pipeline, not a status — the PR-row equivalent of main’s muted “No pipelines yet”. Hover the rows to see the tooltip.

Recommendation: hollow ring in the status slot, tooltip “no pipelines”, no extra row text. Unknown stays purple ?; fix the README.

Recommended — in the real panel

Same 16px slot, same geometry as every other status: a circle. But hollow, no glyph, stroked in --neutral. It holds the column alignment and the eye slides past it. The row still links to the PR; the meta-end drops the time (there is no run time) and keeps the author.

Shape

Everything in the slot is a 16px circle; the ring keeps that rhythm. Hollow = nothing happened here. Solid canceled (slash) and inverted skipped (chevrons) both have a fill and a glyph, so the ring can’t be mistaken for either.

Colour / AA

Stroke is --neutral, 1.5px. ≈3.9:1 on light --bg, ≈3.3:1 on light --hover, ≈7:1 in dark — all over the 3:1 non-text minimum. --border-2 and --text-3 both fail 3:1 in light, so they are out.

Motion

None. Static ring, no transition. Nothing to gate on prefers-reduced-motion.

Semantics

role="img", aria-label="no pipelines", same tooltip action as every other StatusIcon. Row label: #149 title on branch, no pipelines.

The four decisions

1 · Status slot

Hollow ring. 16px, transparent fill, 1.5px --neutral stroke, no glyph. Tooltip + aria-label “no pipelines”. Never notifies, never counts toward the badge or the repo fail-badge.

2 · Copy

“no pipelines”. Agrees with main’s “No pipelines yet” and with the product name. “Checks” is GitHub-only; “CI” is jargon. Drop “yet” on PRs: for a main-only repo nothing is coming, and “yet” would promise one. Lowercase, matching the other StatusIcon labels (“passed”, “failed”).

3 · Row text

None. House rule: icons carry the meaning, the word lives in the tooltip. Inline “no pipelines” text would make the row louder than passing rows, the opposite of the goal. The only visible change is the missing run time.

4 · Unknown

Purple ? is right; fix the README. Unknown now means “the provider sent a status we don’t recognise” — a real anomaly the user (and we) should notice. A grey dot would sit between canceled and the new ring and hide it. Purple is the one hue no other state uses, so it says “exotic” without saying “failed”.

Filter and surfaces

No new chip. Same rule as noPipelinesVisible: these rows show only while every status chip is on; any narrowed filter hides them. They count toward the PR-count chip (they are open PRs) but never toward the fail badge or the notification badge. Identical treatment in side panel, popup and showcase — the showcase gains one row with status: null.
